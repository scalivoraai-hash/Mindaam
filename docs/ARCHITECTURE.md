# Architecture
FastAPI modular monolith, SQLAlchemy 2, Alembic, PostgreSQL/PostGIS for deployment; SQLite is an explicitly local/test fallback. Next.js/React/TypeScript consumer application includes separate /business and /admin portal routes, using backend tenant/RBAC gates. WebGL Three.js procedural local world adapter and independent geospatial provider interfaces; local world is labelled simulated, never photoreal real-map coverage.
All API routes under /api except health. Bearer opaque session tokens, hashed at rest; frontend holds token in sessionStorage for local build. Production authentication security review remains a gate. Atomic ledger writes lock user row in Postgres; SQLite uses BEGIN IMMEDIATE for tests/local. Real GPS used only in verification requests, never presence. Presence authoritative virtual coordinates; sessions authenticated and validated on every operation. External services fail closed when not configured.
Shared backend contract: db.py exposes Base, engine, SessionLocal, get_db. models.py exposes User(id,email,username,password_hash,role,city,privacy,avatar,interests,onboarded,suspended,created_at) and Ledger. auth.py exposes current_user dependency and require_admin. economy.py exposes credit(db,user_id,amount,kind,source,key,currency='credits') operating within caller transaction, no commit. Routers should use db dependency and own atomic transactions. core/commerce models use string UUIDs and epoch float timestamps.
Consumer client uses Authorization: Bearer token. POST /api/auth/register {email,password,username,adult:true,accepted_terms:true}; POST /api/auth/login {email,password}; responses {token,user}. GET /api/me, POST /api/onboarding {city,interests,avatar,privacy,location_consent,analytics_consent}; GET /api/world/{city} returns {city,zone,collectibles,players,businesses,simulated,online}; POST /api/world/enter {city}; POST /api/world/move {dx,dz,mode}; POST /api/collectibles/{id}/claim {}. Position coordinates x,z are virtual metres, server integrates bounded input; no GPS accepted in movement. GET /api/wallet returns {credits,xp,transactions,perks}; POST /api/rewards/daily; GET /api/missions; GET /api/people; POST /api/social/{id}/{wave|follow|friend|accept|block}; GET/POST /api/messages/{id} with {body}; GET/POST /api/crews; POST /api/crews/{id}/join; GET /api/leaderboard; GET/POST /api/events; POST /api/events/{id}/join; GET /api/notifications; GET /api/config; POST /api/reports; GET /api/privacy/export; DELETE /api/me; POST /api/media/request {target_id,kind}; POST /api/media/{id}/{accept|reject|end}; GET /api/media; POST /api/media/{id}/token. Missing providers return structured 503, never simulated success.

## Mapped district adapter — 2026-09-13
Bundled OSM snapshots of Soho, Bullring and Centre:MK use local metric coordinates shared by rendering and server road proximity checks. Coverage is a bounded district, not an entire city. Buildings are stylised extrusions of mapped footprints; incidental street props and labelled NPCs are procedural. Static meshes are batched by material and 80m tile. Authored one-time collection trails and a mission per district use existing authoritative claims and ledger transactions. No merchant partnership is inferred from a map place. OSM attribution and ODbL source metadata ship with each map. Existing synthetic test-fixture adapter stays confined to APP_ENV=test; geographic checks have separate tests.

## Browser sessions and release interactions
Browser authentication uses the existing opaque, hashed server session records with an HttpOnly, Secure-on-HTTPS, SameSite=Lax cookie. Cookie-authenticated mutations require the configured exact Origin and X-Pulse-Client header; cookie WebSockets require exact Origin. Explicit bearer clients remain compatible. Username lookup and uniqueness normalize whitespace and case. Password changes revoke all sessions.

Talk distances and request/cooldown timing are centralized in TALK_INTERACTION_METRES (10), TALK_QUICK_METRES (5), TALK_REQUEST_SECONDS (30), TALK_COOLDOWN_SECONDS (30). MediaSession continues to represent consent; no duplicate interaction tables. Blocking commits revocation before provider cleanup and failed cleanup remains retryable. Mini camera tiles use projected avatar positions without sharing device GPS.

Merchant signage is additive JSON on Business. Only verified, geographically nearby businesses appear as owned Three.js storefront overlays. Category interiors use reusable geometry. Database campaign funding controls reward indicators. Schema migration fc20_release_auth adds signage and normalized username uniqueness; a conflicting existing username must be resolved explicitly before migration, never silently renamed.

## Movement recovery and licensed building signs
Movement now sweeps 20cm substeps and slides along a valid axis when a diagonal step collides. Cached 32m spatial buckets bound road and building collision lookups. District entry uses a cached traversable road spawn (the bundled Birmingham origin was inside a footprint). Invalid positions recover only to nearby safe ground, bounded by WORLD_RECOVERY_METRES (default/maximum 3m). The authenticated Unstuck action has a 30-second cooldown and does not move an already valid avatar. Recovery writes audit events. Position timestamps prevent older snapshots from overwriting newer movement responses.

Building signs use existing licensed OSM names and polygons, choosing a facade near a mapped street with its normal facing out of the footprint. Contained/nearby named shop POIs can supply an unnamed building's fascia; no name is invented. Sign textures are created for at most 64 nearby buildings within 100m, frustum culled, and disposed on departure. Named map locations remain distinct from enrolled reward merchants. LiveFace mini tiles scale with virtual distance and hide beyond 60m or outside the view.

## Targeted social presentation — 2026-09-21
LiveFace has exactly three presentation modes: mini, expanded split screen, and fixed viewport fullscreen. Mode changes do not recreate the LiveKit room. Explicit layout rules clear inherited centering/edge constraints. Accepted/connecting/ended states remain compact; camera-off participants render initials. The control footer wraps independently from video tiles. A join generation cancels an in-flight Join when the user ends it. Existing LiveKit integration remains in place; the additive membership extension below governs group grants.

Optional descriptive profile data lives in the additive `users.profile` JSON column (fd21_profile_display). Registration defaults to Prefer not to say; identity and display location are private by default. Authenticated owner updates use a strict whitelist with length limits. Public people, presence, and talk responses expose only opted-in fields, never raw profile JSON or GPS. Account deletion clears the new profile. Avatar suggestions remain optional; all presets stay selectable.

Reusable world scoreboards use location configuration in WorldScoreboard.ts and poll the existing /rankings endpoint every 30 seconds. Existing collection/mission score calculation is unchanged; own rank is added from the same ordered scores. Canvas texture updates run at most once a second, only when content/LOD changes; geometry is culled beyond 160m, simplified beyond 60m, and disposed on world teardown. View Full Rankings opens the existing rankings UI with all-time XP matching the board. No map/world IDs, geography, movement or economic rules change.


## Proximity groups and avatar communication — 2026-09-21
Migration fe21 extends MediaSession with a root conversation reference, join policy and ending reason. Composite-key memberships and join requests extend that session rather than introducing another chat/message model. Existing accepted pairs are backfilled. Root messages retain their history; approved joining members see it, as disclosed in the approval card. Child voice/video sessions reuse pulse-{session_id}, including when a third member joins. Devices still require an explicit Join gesture. Newly initiated group media requires each invited member's acceptance.

Root-row locks serialize join decisions and capacity checks. Duplicate approval is idempotent. The default capacity is six (bounded to eight); one active member may approve by default, with host-only configuration available. Approval/friends/closed/invite policies restrict discovery and entry; closed/invite currently disable nearby requests. Blocking removes the blocking member from a larger session so remaining users continue, and marks incompatible pending requests blocked. Token grants require active, unblocked, unexpired membership. LiveKit removal includes a revocation cutoff; cleanup retries for 660 seconds cover refreshed token lifetime, while existing room expiry remains ten minutes.

Authoritative Presence coordinates drive start/warning/disconnect defaults of 10/18/25 virtual metres and an eight-second grace. Any nearby active group peer supplies proximity eligibility. Once outside disconnect distance, grace resets only after returning inside warning distance. Each member departs independently; fewer than two members ends the session. Maintenance samples every two seconds and grant/text authorization rechecks eligibility. No per-frame database query or real GPS is used. Client revision/state reconciliation prevents older fallback responses restoring pending UI.

Mini media follows identity-keyed projected avatar anchors sampled at 30Hz, with smoothed positioning, distance scaling, small-screen tile sizing and overlap offsets. Voice/camera-off tiles include names and status, with speaking outlines. Mini hides the text panel until Message is selected. Expanded uses a 44/56 split, vertical on narrow portrait screens, retaining the existing world renderer and input handlers; remote tiles dominate and local video is PiP. Fullscreen retains its video grid. Text histories use content-driven height. Capsule limbs, smaller shaped heads, joint animation and three avatar detail levels share cached geometry. The scoreboard's gradient, medal rows and own-rank highlight change presentation only.


## MyLilWorlds communication and event extension — 2026-09-22
Public branding changes only; internal Pulse identifiers and auth/economy contracts remain stable. Existing MediaSession/ConversationMember records support spontaneous groups; both original participants moderate, guests cannot approve, removal has a 120-second configurable cooldown. Nearby eligibility remains server-authoritative with warning/disconnect hysteresis.

Existing Event/Attendee tables now store event visibility, lifecycle, attendance and stage roles. Event sessions use the same LiveKit token/room pipeline. Event audiences receive subscribe-only grants; promotion/demotion updates provider permissions and retries failed permission updates in maintenance. Event host departure ends the event; spontaneous groups end when both originals leave. Events deliberately use host/attendance eligibility rather than spontaneous proximity disconnect.

Local microphone tracks are rejected before playback attachment; remote tracks are deduplicated. Supported audio processing constraints, per-peer local mute and audio device selectors are additive. No echo-free certification without real-device testing.

Geography remains bundled OSM with 12 additional bounded districts. Multipolygon holes are used consistently in rendering and collision checks. Whitehouse refresh retains original coverage and adds two source-backed school footprints, no claimed additional houses/apartments.

Touch: world input is disabled while registration, onboarding or drawers are active. Native inputs preserve scrolling and pinch zoom. Canvas gestures track one pointer and handle cancellation; joystick capture loss clears motion. Running is 13 virtual metres/second versus walking 6; the existing 0.3-second server movement cap and swept collision checks remain.


## 2026-09-24: world discovery and share access
`world_access` is a permanent (user, destination) entitlement independent from wallet, XP and referral ledgers. Four user-confirmed choices are persisted; onboarding explicitly selects the first. Previewing/searching never grants access. User-row locks serialize starter selection and share accounting; primary/unique keys enforce idempotency. The fifth counted share inserts access in the same transaction. Entry, world snapshots, onboarding location changes and mapped fast travel enforce access. Public map previews remain previews.

Migration fh24 grants every pre-existing account all 17 formerly unrestricted destinations. It does not infer history from passport stamps or revoke previously available access. Future new accounts get no automatically picked worlds. Additional entitlements count toward the initial four-access allowance.

Sharing means an explicit composer-open, successful clipboard copy or resolved native-share action. External publication and recipient signup are not verified or required. Native cancellation and blocked popup/clipboard errors do not count. One UUID survives retry; a configurable per-user 5-second cooldown prevents accidental duplication across destinations. Invite codes contain 144 bits of randomness and public lookups expose destination context, never sharer identity.

Optional growth telemetry respects existing analytics consent. Functional access/share records persist regardless of telemetry consent. Anonymous invite-open aggregates store no recipient identity/IP/fingerprint. Acquisition attribution is optional, separate from unlock eligibility and existing referral rewards. Admin metrics expose aggregates only. The frontend loads all enabled/public/joinable destinations and refreshes activity every 15 seconds.

## 2026-09-25: connected city platform
The existing FastAPI/Next.js application gains transit, supported public interiors, and a restricted `/super-admin` route. Migration `fi25_city_platform` is additive: existing Users, Presence, MediaSession and Event records gain fields; transport, enquiry/campaign, interior-visit and activity tables are added. Authentication, maps, existing chat/LiveKit rooms, world entitlements and reward ledgers remain the source of authority.

Presence `zone_id` separates world, bus, building and event spaces. The world renderer consumes the same snapshot contract and projects media tiles from real participant identities. Public interior templates do not claim to reproduce surveyed interiors. Auditorium audiences stay off the stage until a host promotes them; the current media room controls publish grants. Standard events retain their presentation. Stage mini-video placement is scoped to auditorium hosts; split/fullscreen layouts retain the existing implementation.

Transport routes are a per-country interchange network over enabled destinations. Each route has persisted frequency, duration, fare and capacity. Vehicle instances snapshot fare/capacity; tickets and seat claims serialize on database row locks. The immutable Credits ledger deduplicates purchase IDs, and a unique user/vehicle ticket prevents retry charging with a second ID. No destination purchase bypasses world access. Source and destination approaches follow approved bundled driving segments; the intercity interval is explicitly compressed, not a claim of a continuous nationwide road map. Server stop windows prevent getting off a moving vehicle. Fast travel and city changes cannot bypass an active journey. Shared passenger identities require fresh authenticated presence; stale passengers do not inflate counts. Refresh resumes a saved journey.

Mutual Friends use existing Social records. Accept, cancel, decline, remove and block are idempotent or state-checked. Friend conversations still require the existing request acceptance and device Join gesture; two-member friend sessions may cross virtual worlds. Proximity sessions and larger groups retain their existing distance rules. Room creators/original moderators may set a session maximum, bounded by `TALK_MAX_PARTICIPANTS` (default hard cap 8, environment ceiling 10); new pair sessions keep default capacity 6.

Advertising enquiries are persisted with consent and duplicate/rate guards. Active scheduled campaigns replace fallback boards and expire automatically. Creative uploads are restricted to owner admins with size/type limits; no arbitrary remote fetch or script creative is accepted. Ad tracking respects analytics consent and validates the current board/campaign/world. The admin portal uses the existing session and strict `super_admin` permission on every endpoint. Operational history begins at deployment; no history is fabricated. Owner bootstrap requires three deployment secrets, refuses implicit elevation of existing accounts, creates at most one owner, and gates admin access until the initial password is changed.

The final review separates new venue arrivals under the venue row lock and allocates an available initial bus seat while preserving later seat choice. World rendering limits auditorium peers to 48 real nearby participants, prioritising stage roles; the underlying event/media capacity remains separate. Front/back camera presets use avatar heading. Interior/window bus views place the camera onboard and use transparent glazing; external view retains orbit. Map fallback intentionally hides 3D camera controls. These visuals still need real GPU/device acceptance.

Ticket purchase and auditorium gift requests include the user-reviewed fare/cost. The server rejects a stale quote before charging. Departure boards use the immutable active vehicle snapshot, while retries retain ledger idempotency and the original charged gift cost.

## Combined release profile extension — local, not released
The existing users.profile JSON now stores bounded display name, bio, public interests, languages, themes and visibility-controlled HTTPS social links. ### 2026-10-28 compatibility decisions

`events.venue_mode` is nullable for old rows. Explicit new modes determine `venue_experience_type` and the server-owned arena reservation requirement. Old auditorium rows resolve to Grand Arena only when an existing booking or historical reservation flag requires it; other old auditorium rows remain virtual. Existing reservation receipts are never rewritten by this mapping.

Consumer payment refunds recover Credits through additional immutable ledger rows. Outstanding recovery pauses spending and is settled against later Credits without allowing a negative balance. Open disputes pause spending; signed terminal outcomes release the hold or recover the lost payment. Cumulative refunds and terminal dispute states resist duplicate/out-of-order delivery. Provider payment-intent mapping, tenant-owned status polling, and sandbox key/event guards extend the existing Checkout/webhook endpoints. Merchant funding reversals remain explicitly unacknowledged pending reconciliation; this correction does not invent merchant refunds or cash-out.
